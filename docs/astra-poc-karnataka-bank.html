Section 1 · Purpose

Purpose of This Document

This document sets out the proposed end-to-end process, testing methodology, activities, responsibilities, prerequisites, controls, acceptance criteria and indicative timelines for conducting a controlled live Proof-of-Concept (POC) of the ASTRA Intelligent CTS Processing Platform with Karnataka Bank Ltd.

It is intended to give all stakeholders — technology, operations, compliance, and senior leadership — a common operating plan before technical integration and live testing commence. The plan will be reviewed and confirmed on-ground at Stage 1 before any integration work begins.

The methodology is designed around the RBI continuous clearing framework and is intended to minimise disruption to the bank's existing CTS environment throughout the evaluation.

Section 2 · Regulatory Context

Regulatory Context and Testing Objective

The RBI circular dated 13 August 2025 introduced Continuous Clearing and Settlement on Realisation in CTS. Phase II, effective 3 January 2026, prescribes that the Item Expiry Time (IET) for each inward cheque is T+3 clear hours. For example, instruments received by the drawee bank between 10:00 AM and 11:00 AM are to be confirmed by 2:00 PM. Items for which confirmation is not provided within the prescribed three hours are treated as deemed approved and included for settlement regardless of the instrument's merit.

Accordingly, this POC should not be treated merely as an AI accuracy demonstration. It must test the complete operational chain and establish whether ASTRA can reliably process inward instruments within the available clearing window while maintaining decision accuracy, full auditability, operational resilience, and safe fallback to the existing process at every step.

ASTRA's architecture — parallel agent-per-instrument processing, continuous per-instrument timer monitoring with configurable escalation thresholds, and direct hand-off to the existing CTS vendor for NGCH filing — has been designed specifically for this operating environment. The POC validates this architecture against Karnataka Bank's own volume profile, data characteristics, and operating conditions.

Section 3 · Objectives

Objectives of the POC

Processing & Accuracy
  • Demonstrate end-to-end inward cheque processing through ASTRA using Karnataka Bank-relevant data and operating conditions
  • Validate OCR/MICR extraction, image-quality handling, alteration detection, signature comparison, CBS checks, and return-reason determination
  • Validate Positive Pay System (PPS) checks where applicable to Karnataka Bank's portfolio
  • Validate outward pipeline — MICR extraction, CTS-2010 compliance, IQA scoring, lot formation, endorsement, and Presentment File (CXF) generation
Timing & Operational
  • Measure elapsed time from receipt of each inward instrument through automated validation, exception handling, and final decision
  • Demonstrate continuous per-instrument timer monitoring with configurable escalation thresholds aligned to the RBI T+3 clearing window
  • Validate human-review operator productivity and the ability of operators to take informed decisions within the remaining clearing window
  • Validate duplicate detection — no instrument processed twice, whether inward or outward
Integration & Resilience
  • Validate RRF generation, secure hand-off to the existing CTS vendor via SFTP, and avoidance of duplicate return filing
  • Validate graceful degradation when CBS is unavailable, SFTP is interrupted, or GPU inference is delayed — no silent failures
  • Validate operational alerts, audit trails, exception handling, and session reconciliation
Benchmark & Decision
  • Benchmark ASTRA's STP performance against Karnataka Bank's current process, using baselines provided by the bank before Stage 3 calibration
  • Validate operational dashboards and the completeness of the audit trail — every instrument, every decision, every timestamp
  • Establish a controlled, evidence-based foundation for deciding whether to proceed from shadow mode to a limited live production pilot and subsequently to broader deployment

  • Receives live inward instruments for the full PU from CTS vendor mirror

  • Continuous per-instrument timer tracking with configurable alert thresholds, agreed with the bank before go-live

Section 14 · Glossary

Key Terms

CTS
Cheque Truncation System — RBI's electronic clearing framework under which physical cheques are processed as digital images.
IET
Item Expiry Time — the clearing window (currently T+3 clear hours under RBI's Phase II mandate) within which each inward instrument must be confirmed or returned. Items not actioned within IET are deemed approved.
STP
Straight-Through Processing — instruments processed to a final decision (pass or return) by ASTRA without any manual operator intervention.
RRF
Return Reason File — the NPCI-standard file containing return decisions and their reason codes, submitted to NGCH by the drawee bank's CTS vendor.
CXF
Clearing XML File — the NPCI-standard Presentment File generated from outward cheques, submitted by the presenting bank's CTS system to NGCH.
NGCH
National Grid for Cheque Clearing — NPCI's clearing infrastructure. During the POC, NGCH connectivity is retained by the existing CTS vendor throughout.
MICR
Magnetic Ink Character Recognition — the machine-readable band at the bottom of every CTS cheque containing cheque number, MICR code, and account details.
PPS
Positive Pay System — RBI-mandated cross-check for high-value cheques where the drawer pre-registers cheque details with their bank.
IQA
Image Quality Assessment — automated scoring of cheque image quality against NPCI's 16-parameter standard before processing or submission.
CBS
Core Banking System — Karnataka Bank's internal banking platform (e.g. Finacle, BaNCS, Flexcube). ASTRA connects read-only for account status, balance, and stop-payment lookups.
SFTP
Secure File Transfer Protocol — used to exchange cheque image bundles (inward mirror, outward scanner feeds) and output files (RRF, CXF) between ASTRA and the existing CTS vendor.
PU
Processing Unit — the full scope of a bank's CTS inward and outward processing, encompassing all branches and clearing zones under a single bank code.
