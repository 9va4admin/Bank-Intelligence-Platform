PHASE 08 Compliance, Drawee, Exceptions, Auth Audit Log
4 new endpoints 5 screens wired ~3 days
Backend work
GET/v1/cts/inward/sessionsNEW
Inward sessions grouped by presenting bank IFSC — for CTSDraweeView. Returns presenting_bank counts per session window.
SELECT presenting_ifsc, COUNT(*) total, COUNT(*) FILTER(WHERE decision='STP_RETURN') returned, MAX(processing_started_at) last_seen FROM cts.agent_decisions GROUP BY presenting_ifsc ORDER BY total DESC
GET/v1/cts/outward/complianceNEW
CTS-2010 field validation failures — instruments rejected at IQA/compliance stage with specific field-level failure reasons.
SELECT * FROM cts.outward_scan_events WHERE outcome='CTS_REJECTED' AND bank_id=$1 ORDER BY scanned_at DESC LIMIT 200
GET/v1/cts/outward/discrepanciesNEW
MICR/amount mismatch items per branch — feeds CTSDiscrepancy branch-level breakdown.
SELECT presenting_ifsc, COUNT(*) mismatches, MAX(created_at) last_seen FROM cts.mismatch_resolution_items WHERE bank_id=$1 AND status='OPEN' GROUP BY presenting_ifsc
GET/v1/cts/exceptionsNEW
CRITICAL/HIGH priority items from human_review_items — used by CTSExceptions and CTSPipelineVisualizer (Phase 5).
SELECT * FROM cts.human_review_items WHERE bank_id=$1 AND priority IN ('CRITICAL','HIGH') AND status='PENDING' ORDER BY assigned_at DESC LIMIT 100
GET/v1/admin/auth/login-logNEW
Auth event audit log for LoginLog.jsx — found during App.jsx route scan. Returns LOGIN_SUCCESS, LOGIN_FAILED, MFA_VERIFIED, LOGOUT events with immudb Merkle proof status. SB scope: all tenants. SMB scope: own bank_id only.
Query: platform.audit.events WHERE event_type LIKE 'AUTH_%' AND bank_id=ANY($1) ORDER BY occurred_at DESC · immudb_verified = run inclusion proof check per event (or batch verify and cache 60s)
