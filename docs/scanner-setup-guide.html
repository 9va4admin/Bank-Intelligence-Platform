Section 1
Hardware & PC Prerequisites
Scanner Hardware
✓
Canon CR-120 or Canon CR-150
Standard duplex (front+rear). USB or network interface.
✓
Canon CR-120 UV or Canon CR-150 UV
UV-lamp variant. Required for ultraviolet image capture (enable_uv_scan = true).
✓
MICR font: E13B (RBI / NPCI standard)
CMC-7 is not supported. CR-120/150 hardware MICR head is E13B only.
✓
Canon USB scanner driver installed
Required even for network-connected scanners.
Teller PC Requirements
✓
Windows 10 or Windows 11
64-bit OS is fine; the agent process runs as 32-bit (GOARCH=386 for CGO/CSD API).
✓
Administrator rights during install
Needed to register the Windows service and set NTFS ACL on token.dat.
✓
Outbound HTTPS (port 443) to ASTRA server
Internal bank network — not internet. mTLS termination at Istio Ingress Gateway.
✓
USB port (or network path for IP-mode scanners)
One scanner per teller PC. Multiple scanners per PC are not supported.

Section 2
Canon CSD SDK Dependency

The ASTRA scanner agent uses the Canon CSD (CanoCheetah SDK) to communicate with CR-120/CR-150 hardware. The SDK is a Windows DLL. The agent loads it at runtime — the DLL must be present on the teller PC.

Required Files (from Canon)
✓
CanoCheetah.dll
Primary CSD API DLL. Supplied by Canon under OEM agreement.
✓
Any CSD dependencies listed in Canon's deployment note
Typically MSVC runtime DLLs (VC++ Redistributable).
DLL Location
✓
Same folder as astra-scanner-agent.exe (default)
Or set csd_dll_path in config.ini to an explicit path.
✓
System PATH also searched
If DLL is already in C:\Windows\System32 or similar, no copy needed.
⚠️
32-bit process requirement: The CSD API is a 32-bit DLL. The agent binary is compiled with GOARCH=386 and loads the DLL via CGO. The agent will not start on a 64-bit build. The ASTRA CI pipeline enforces this — do not change the GOARCH setting.

Section 3
Installation & Registration
🔑
Phase 1
Generate Registration Code
Ops Manager · Bank HQ
1
Open Branch Master
Navigate to Admin → Branch Master. Confirm Scanner Mode is SDK_PUSH and Status is Active. Branches in FOLDER_DROP or UI_UPLOAD mode do not receive a scanner token.
2
Click Register Scanner (🔑)
A key icon appears on every SDK_PUSH row. Click it to open the Registration panel for that branch.
3
Click "Generate Registration Code"
ASTRA creates an 8-character one-time code tied exclusively to this branch. A 24-hour countdown starts. The code appears in large monospace type.
🔐 One active code per branch. Generating a new code invalidates any previous pending code.
📞
Handoff
Secure Code Delivery
Ops Manager → Branch IT
4
Read the code to Branch IT Coordinator
Call the coordinator and read the 8-character code (e.g. "SARAS-3X7Q"). Use secure internal messaging — not plain email or SMS.
🔐 Code expires in 24 hours and is single-use. It only works for the exact branch it was generated for.
💻
Phase 2
Run Installer at Branch
Branch IT Coordinator · Teller PC
5
Download installer from IT portal
Download ASTRA-Scanner-Setup-v{version}.exe from the bank's internal software portal. Verify SHA-256 checksum before running.
6
Run as Windows Administrator
Right-click → "Run as administrator". Accept the UAC prompt. Admin rights are required to install the Windows service and set NTFS ACL on token.dat.
7
Enter exactly 2 fields
ASTRA Server URL (same for all branches) and Registration Code (from Ops Manager).
🔐 No branch name, no branch ID — the server returns these. Branch identity cannot be forged.
8
Click "Verify →"
The installer contacts ASTRA, submits the code and PC's COMPUTERNAME, and receives all branch config automatically. A green tick confirms success.
⚡
Automatic
Server-Side Exchange
ASTRA Platform · No human action
9
Code atomically consumed from Redis
Server executes a single atomic GETDEL on scanner_reg:{bank_id}:{code}. Code is gone the instant it is read.
🔐 Atomic single-use: even if the request arrives twice simultaneously, only one exchange succeeds.
10
Machine-bound token issued
Server generates a random API token bound to COMPUTERNAME of this PC. It will not authenticate from any other machine.
11
Full config returned
Response: branch_id, bank_id, bank_ifsc, api_url, endorsement_text, enable_imprinter, enable_uv_scan, and raw API token (shown once — never stored on server).
✅
Phase 3
Scanner Goes Live
Installer → Windows Service → Teller PC
12
config.ini written
Non-secret configuration saved to installation folder. Readable by any Windows user — contains no credentials.
13
token.dat written (restricted NTFS ACL)
API token saved to token.dat. NTFS ACL: Read/Write for SYSTEM and Administrators only. Standard teller accounts cannot read this file.
🔐 Even if the teller's Windows account is compromised, the token is inaccessible.
14
ASTRAScannerAgent service installed and started
Registered as a Windows service, set to Automatic (start on boot). Starts immediately. The branch appears as IDLE on the Branch Scan Monitor within seconds.
15
✅ Scanner operational — teller can begin
Load cheques into the Canon CR-120/CR-150 feeder. Each cheque is captured (front + rear TIFF, hardware MICR, optional UV) and submitted to ASTRA CTS.

Installed Files
# Default install path: C:\Program Files\ASTRA\ScannerAgent\ astra-scanner-agent.exe ← main binary (32-bit, GOARCH=386) CanoCheetah.dll ← Canon CSD SDK DLL (placed by installer) config.ini ← non-secret configuration (world-readable) token.dat ← API bearer token (NTFS: SYSTEM+Admins only) astra-scanner-agent.log ← structured JSON log (slog, rotated daily)
ℹ️
After a PC replacement or rebuild, re-run the installer with a fresh registration code. The old token is revoked automatically. The old config.ini can be reused as a starting point but token.dat must be regenerated — it is machine-bound.

Section 5
config.ini Reference

All keys are read at startup. Changes require a service restart (sc stop ASTRAScannerAgent && sc start ASTRAScannerAgent). In CI / dev environments without config.ini, the agent falls back to environment variables (see Env Var column). No value in this file is a secret — the API token lives exclusively in token.dat.

# Minimal config.ini written by the installer # All values below can be edited without a rebuild [astra] api_url = https://astra.yourbank.in bank_ifsc = SVCB0000001 bank_id = saraswat-coop branch_id = BRANCH-ANDHERI-01 # api_token is NOT here — it lives in token.dat [scanner] discovery_mode = usb scan_dpi = 300 ; NPCI guideline; CTS-2010 minimum is 200 scan_mode_value = 16 ; 16 = binary fine-text enable_uv_scan = false ; true only on UV-equipped models enable_imprinter = true endorsement_text = ASTRA/CTS enable_iqa = true mocr_weight = 50

[scanner] section — image capture quality
Key
Default
Env Var
Description
scan_dpi
300
SCANNER_DPI
Scan resolution in DPI. Applied to both X and Y resolution (CSDP_XRESOLUTION + CSDP_YRESOLUTION).
NPCI guideline: 300 DPI. CTS-2010 regulatory minimum: 200 DPI. Do not go below 200.
scan_mode_value
16
SCANNER_MODE_VALUE
Value passed to CSDP_MODE. Controls colour depth.
16 = binary fine-text mode (recommended for cheque processing). Other values select grayscale or colour. Confirm from CsdScan.h or Canon documentation.
mocr_weight
50
SCANNER_MOCR_WEIGHT
MICR OCR fusion weight: 0 = pure magnetic (hardware MICR head only), 100 = pure optical (camera OCR only). 50 = equal blend.
Increase toward 100 for scanners with aging magnetic heads. Decrease toward 0 for maximum accuracy on clean instruments.
feeder_poll_ms
300
SCANNER_FEEDER_POLL_MS
Sleep duration in milliseconds between feeder-empty restart attempts. Controls how quickly the agent responds when a teller loads the next cheque batch.
Lower values are more responsive but increase CPU usage. 200–500 ms is a reasonable range.

Section 6
UV Scanner Setup
⚠️
UV hardware required: UV image capture is only available on the Canon CR-120 UV and Canon CR-150 UV variants. Standard CR-120/CR-150 scanners do not have a UV lamp. The model variant is printed on the scanner label.

How UV capture works (3-pass sequence)

When enable_uv_scan = true, the CSD API performs three CsdReadPage calls per cheque instead of two:

1️⃣
Pass 1 — Front
Front face TIFF image + hardware MICR line
2️⃣
Pass 2 — Rear
Rear face TIFF image. Front released after saving both.
3️⃣
Pass 3 — UV
UV lamp image. Reveals security printing not visible under white light.

Setup checklist

✓
Confirm scanner model is CR-120 UV or CR-150 UV (check label)
✓
Set enable_uv_scan = true in config.ini [scanner] section
✓
Verify uv_param_id = 380 against CsdScan.h in your SDK package
✓
Restart the ASTRAScannerAgent Windows service
✓
Run a test scan — the Branch Scan Monitor item detail should show a UV image thumbnail
✓
Check agent log for: "UV lamp enabled" — if you see "UV lamp enable failed", the uv_param_id offset is wrong
ℹ️
A UV enable failure is a warning, not a fatal error. The agent continues scanning without UV and logs a warning. Scanning is never blocked by UV setup issues — IET compliance is never at risk.

Section 7
Agent Heartbeat & States

The agent sends a heartbeat to ASTRA every 30 seconds for the lifetime of the process. Each heartbeat includes the branch_id, bank_id, and the active session ID (if a session is running). ASTRA uses this to maintain the 3-state status visible in the Branch Scan Monitor.

ACTIVE
When:
Heartbeat received within the last 90 seconds AND a scan session is currently running (teller has called POST /session/start).
IDLE
When:
Heartbeat received within the last 90 seconds but no session is running. Service is online and ready — teller has not started a scan session yet.
OFFLINE
When:
No heartbeat received in the last 90 seconds. Service may be stopped, PC is off, or network is unreachable from ASTRA.
ℹ️
No clearing schedule needed. The heartbeat threshold does not need to be configured to match banking hours. OFFLINE alerts during clearing hours matter; OFFLINE overnight does not — tellers don't start sessions on holidays and PCs may be powered off after hours. ASTRA ops staff understand this context.
What the Branch Scan Monitor shows
The Branch Scan Monitor (React page in ASTRA CTS UI) combines two data sources:
  • Hardware events — instant, from the scan-events endpoint. Shows scan-start, double-feed, re-scan, jam.
  • Workflow outcomes — polled, from scan-monitor/recent. Shows ACCEPTED / REJECTED / HELD per instrument after the CTS inward workflow completes.

Section 8
Build from Source

The agent binary is built by CI and distributed via the bank's internal software portal. Bank IT teams should not need to build from source. This section is for ASTRA developers and advanced troubleshooting.

Go Architecture
GOARCH=386
32-bit required. The Canon CSD API (CanoCheetah.dll) is a 32-bit DLL and can only be loaded from a 32-bit process via CGO.
Target OS
GOOS=windows
Windows only. The real CSD implementation is in ranger_windows.go (build tag: windows && cgo). Non-Windows builds use a stub transport.
CGO Compiler
MinGW-w64 (i686)
Cross-compilation from Linux CI: use i686-w64-mingw32-gcc. On Windows: install MSYS2 and select the mingw32 toolchain.
CGO Status
CGO_ENABLED=1
CGO must be enabled for the CSD API header bindings to compile. CGO_ENABLED=0 produces a stub-only binary with no hardware support.
# Build from Linux CI (cross-compile for Windows 32-bit) GOOS=windows GOARCH=386 CGO_ENABLED=1 \ CC=i686-w64-mingw32-gcc \ go build -o astra-scanner-agent.exe ./edge/cts-scanner-agent/ # Build on Windows (requires MinGW-w64 i686 in PATH) set GOARCH=386 set CGO_ENABLED=1 go build -o astra-scanner-agent.exe ./edge/cts-scanner-agent/ # Run tests (non-CGO stub, works on any platform) go test ./edge/cts-scanner-agent/ -v -count=1
✅
Test suite: 29/29 tests pass on any platform (Linux, Windows, macOS) without CGO. Tests cover config defaults, DPI override, UV URL presence, heartbeat success/error, session state, and scanner item flags.

Section 9
Security Design
🔒
Branch ID is server-authoritative
The IT coordinator enters zero branch identity. The server returns it from YugabyteDB. Forgery is impossible.
⚡
Single-use code (atomic)
Redis GETDEL — code vanishes on first successful exchange. No replay window.
🖥️
Machine-bound token
Token stored with machine_id = COMPUTERNAME. Fails authentication from any other PC.
🛡️
token.dat unreadable by users
NTFS ACL: SYSTEM + Administrators only. Standard teller account cannot read it.
⏰
24-hour code expiry
Unexchanged codes auto-expire from Redis. No dangling codes survive past installation window.
🔑
One active code per branch
Generating a new code invalidates the previous. No duplicate registrations possible.

Section 10
Troubleshooting
?
"Invalid code" error on Verify
Code has been used or expired (24-hour limit). Ask Ops Manager to generate a new code from Branch Master.
?
Service installs but scanner shows OFFLINE in Branch Scan Monitor
Check: (1) Outbound HTTPS port 443 to ASTRA server allowed from teller PC. (2) Canon scanner USB driver installed. (3) Service status: sc query ASTRAScannerAgent. (4) Check log at astra-scanner-agent.log for the startup error.
?
Branch shows IDLE — teller cannot start session
IDLE means the agent is running but no session is active. The teller UI must call POST /session/start to begin scanning. If the UI button is disabled, check that the teller PC's scanner agent is on the same local port (listen_addr = :9201) the UI is configured to call.
?
Scanner found but scans fail immediately — no images produced
Check CanoCheetah.dll is present in the exe directory or system PATH. Then check log for "CSD open failed" — this means the DLL loaded but the scanner session could not be opened. Confirm the scanner USB cable is connected and the Canon driver is installed.
?
IQA failures — good cheques flagged as bad quality
Two causes: (1) Wrong IQA param IDs — verify iqa_brightness_param_id and iqa_result_param_id against CsdScan.h for your SDK version. (2) Lighting or scanner dirty — clean the scanner glass. Alternatively disable IQA temporarily with enable_iqa = false to confirm it is a config issue.
?
UV scans not appearing in Branch Scan Monitor item detail
Check log for "UV lamp enable failed". If present, the uv_param_id is wrong — confirm the correct offset from CsdScan.h for your CSD SDK version and update config.ini. Restart the service. If log shows "UV lamp enabled" but no image appears, the scanner model may not be a UV variant.
?
Need to re-register after PC replacement
Ask Ops Manager for a fresh registration code. Run the installer on the new PC — it revokes the old machine-bound token automatically and issues a new one. The old config.ini can be copied to the new PC as a starting point; delete token.dat before running the installer.
?
Where are the logs?
Structured JSON logs (slog format) in astra-scanner-agent.log in the installation folder. To tail on Windows: Get-Content "...\astra-scanner-agent.log" -Wait -Tail 50 in PowerShell. Look for "level":"ERROR" entries first.
?
Agent starts but MICR values are garbled
Adjust mocr_weight. A value of 100 (optical only) avoids the magnetic head entirely if the head is faulty. Values around 80–90 work well for aging hardware. A value of 0 (magnetic only) is best when cheques are clean and hardware is maintained.
