02 · Cascade Orchestrator

L1 → L2 Escalation Logic

Shared orchestrator in shared/ai/model_cascade.py that decides whether to run the 7B model (fast, cheap) or escalate to 72B (accurate, expensive). ~90 % of cheques clear at L1 in <100 ms; average wall-clock drops from ~500 ms to ~150 ms.

Escalation Trigger 1 L1 confidence < ai.cascade.l1_confidence_threshold (config, default 0.85)
Escalation Trigger 2 Cheque amount ≥ ai.cascade.high_value_threshold — L2 always forced for high-value (default ₹50 lakh)
Escalation Trigger 3 L1 unavailable (vLLMUnavailableError / TimeoutError) → immediate L2 retry
Kill switch: ai.cascade.l2_escalation_enabled = false forces all results through L1 only (ops override, e.g. GPU contention during peak clearing window).
03 · Inward Pipeline (Drawee Bank)

ChequeProcessingWorkflow — Step by Step

One cheque = one Temporal workflow. 500 cheques in a batch = 500 parallel workflows. Each must produce a decision in <600 ms p99 with IET breach rate of 0.000 %.

AI model (vLLM / SNN / XGBoost)
Local NLP / CPU model (no vLLM)
Rule-based / no AI
01
Inward Bundle Received
Rule
NGCH inward file arrives via SFTP. Bundle is split per cheque. Each instrument gets a workflow ID: cts-{bank_id}-{instrument_id}. Kafka topic: cts.inward.{bank_id}.
02
IET Watchdog Spawned
Non-negotiable
Always the very first child workflow — IETWatchdogWorkflow starts before any processing. Fires an emergency NGCH filing at T−30 s before IET deadline regardless of processing state. parent_close_policy = ABANDON — watchdog survives even if parent crashes.
Config key: iet_minutes (default 180) Emergency threshold: T−30 s (structural, not configurable)
03
Vision AI Kill Switch Lookup
Rule · Config
Resolves the RBI Vision AI Kill Switch mode for this instrument via VisionAIKillSwitch.check(). Two separate modes: KC (Kill Complete) — Vision AI is NOT called at all; activity immediately returns requires_human_review=True. KP (Kill Proposed) — Vision AI runs normally, but the decision backstop forces HUMAN_REVIEW regardless of result. NONE = normal path.
Activity: get_kill_switch_status Scope: GLOBAL | SB_OWN | SMB
04
OCR Extraction — Stage 1
AI · GOT-OCR2.0
L1: cts-ocr-l1 (got-ocr2-7b) → L2: cts-ocr-l2 (got-ocr2-full) · CascadeOrchestrator
Full-image OCR via CascadeOrchestrator. Extracts: MICR line (E-13B), amount in figures, amount in words, date (D/M/Y), payee name, drawer name, bank name, branch. Returns per-field confidence scores. Low-confidence fields trigger Stage 2.
Outputs micr_line amount_figures amount_words payee_name date ocr_confidence cascade_level
05
Indic OCR Refinement — Stage 2
Local · IndicOCR
Direct HTTP · CPU sidecar · timeout: 10 s per zone
Optional second pass using PaddleOCR (IndicOCR) for payee name and amount_words zones when Indic script is detected. Covers 9 scripts. Skip if cts.indic_ocr.kill_mode = KC or zone confidence already above threshold.
Trigger: Indic script detected OR GOT confidence < threshold Config: ocr.indic.enabled, indic_ocr.kill_mode
06
Signature Detection
AI · Qwen2-VL 7B
queue: cts-vision-l1 · timeout: 60 s · retry: 2
Detects ink signature bboxes on the cheque image. Returns fractional coordinates [x1,y1,x2,y2] and fraud flags: OVERWRITTEN · SMUDGED · MULTIPLE_INKS · FAINT_INK · MISALIGNED. Count determines routing: 1 sig → S-SVS (single signatory vault); ≥2 sigs → M-SVS (mandate BRE).
Outputs sig_count sig_bboxes fraud_flags
07
Alteration Detection
AI · Qwen2-VL Cascade
L1: cts-vision-l1 (7B) → L2: cts-vision-l2 (72B) if escalated
CascadeOrchestrator runs Qwen2-VL to detect physical alterations. Analyses ink physics (pressure inconsistency, bleed anomaly, flow reversal), paper fibre (distortion, gloss patches), correction fluid (luminance spikes, edge sharpness), and chemical alteration. High tamper_risk_score → human review.
Outputs alteration_detected tamper_risk_score physical_anomaly_score altered_fields anomaly_breakdown cascade_level
08
CTS-2010 Security Features
AI · Qwen2-VL 72B
queue: cts-vision · timeout: 90 s · direct 72B (no cascade) · primarily outward path
Validates 4 mandatory CTS-2010 printed security features: void pantograph, rupee symbol (₹), micro-lettering, printer name per CTS-2010. Missing feature → compliance violation → routed per bank policy. Returns per-feature confidence and boolean present/absent. Applied primarily on the outward (presentee) path.
Outputs void_pantograph rupee_symbol micro_lettering printer_name_cts2010 per-feature confidence
09
UV Security Analysis
AI · Qwen2-VL 72B
CascadeOrchestrator (cts-vision-l1 → cts-vision-l2) · timeout: 120 s per call
Analyses the UV-spectrum cheque image for three RBI-mandated UV features: pentograph authenticity (UV-reactive void pattern), security thread (presence, position), and UV watermark. All three must pass for uv_security_passed = true. Uses orchestrator.call_vision() — L1 (7B) handles routine cases; L2 (72B) forced for high-value or low-confidence.
Outputs pentograph_authentic security_thread_present uv_watermark_present uv_security_passed uv_risk_score
10
Signature Verification
AI · Siamese SNN
Direct HTTP :8020 · timeout: 15 s · retry: 2
Pre-processes each detected sig crop (Otsu binarisation + Zhang-Suen thinning), embeds into 512-dim vector via astra-sig-encoder-v1. Computes cosine similarity against ALL vault specimens for the account. Vault key: sig:{bank_id}:{hmac_sha256(account)}. CBS fallback if vault miss: fetch specimens from CBS → embed → store → compare.
Vault miss action: always HUMAN_REVIEW (Layer 1 enforced — never AUTO_RETURN)
Outputs sig_match_score match_decision specimens_compared
11
Mandate BRE (Multi-Signatory)
Rule · BRE
Business Rule Engine evaluates multi-signatory mandate: ANY_ONE (at least 1 sig matches — default / SMB), ALL_REQUIRED (every signatory must match), QUORUM_N (N of M must match). Triggered only when sig_count ≥ 2 in step 06.
12
Fraud Scoring
AI · XGBoost + SHAP
Direct call · CPU · timeout: 10 s
XGBoost ensemble scores fraud probability from structured features (OCR fields, account metadata, clearing history, anomaly flags from earlier steps). SHAP TreeExplainer always runs — values stored in decision.shap_values before any NGCH filing. Rule-based fallback if XGBoost unavailable.
Outputs fraud_score (0–1) shap_values feature_importances
13
Fraud Rationale Synthesis
AI · Llama 3.3 70B
queue: cts-reasoning · timeout: 180 s · Headroom 75–82 % compression
Llama 3.3 70B converts XGBoost score + SHAP top-N features into a plain-English explanation for the bank officer. Prompt is compressed locally by Headroom before GPU send (75–82 % token reduction). Temperature 0.1, max_tokens 300. Never includes raw account numbers or full customer names.
Outputs fraud_rationale (text) key_risk_factors
14
Decision & NGCH Filing
Decision Engine
Aggregates all AI signals against config thresholds and routes to one of four outcomes:
STP_AUTO_CONFIRM — all clear, fraud score below STP threshold → NGCH HONOUR
HUMAN_REVIEW — any signal above human_review threshold → 55-min HumanReviewWorkflow
AUTO_RETURN — clear policy violation (stopped instrument, CTS-2010 fail, kill switch)
NGCH_FILED — honour or return filed via ngch_filer activity (exactly-once)
SHAP required: always before filing Audit: Immudb write + HSM sign after every YugabyteDB write
04 · Outward Pipeline (Presentee Bank)

OutwardScanWorkflow — Step by Step

Outward processing handles cheques presented by the bank's own customers. Starts with physical scanning at the branch counter and ends with lot submission to NGCH.

AI model (vLLM)
Local NLP / CPU (no vLLM)
Rule-based / no AI
01
Physical Scan
Hardware
Branch scanner captures front and back at 200 DPI colour. MICR band read by scanner hardware (E-13B font, physical read — not AI). Raw image + MICR data forwarded to OutwardScanWorkflow.
02
CTS-2010 Image Quality Validation
Rule · No AI
Rule-based checks — no AI involved. Validates: DPI ≥ 200, colour depth = 24-bit, file_size_kb within bounds, IQA score (image quality assessment via OpenCV), MICR band score. Reject-at-counter if any check fails — cheque returned to customer before lot creation.
Activity: validate_cts2010
03
OCR Extraction — Stage 1
AI · GOT-OCR2.0
L1: cts-ocr-l1 (got-ocr2-7b) → L2: cts-ocr-l2 (got-ocr2-full) · CascadeOrchestrator · timeout: 30 s
Same OCR pipeline as inward. Extracts all printed fields from the captured image. MICR hardware read is used as ground truth for MICR line; GOT-OCR2.0 fills in all other fields. Low-confidence fields escalate to Stage 2.
Outputs amount_figures amount_words payee_name date ocr_confidence
04
Indic OCR Refinement — Stage 2
Local · IndicOCR
Direct HTTP · CPU sidecar · timeout: 10 s per zone
Same as inward Step 05. Refines payee name and amount_words for Indic-script cheques using PaddleOCR. Optional — triggered by script detection or low L1 confidence in those zones.
05
Signature Detection
AI · Qwen2-VL 7B
queue: cts-vision-l1 · timeout: 60 s
Detects ink signature presence and location on the outward cheque. CTS-2010 requires a signature — ABSENT result → immediate reject-at-counter with return reason code. PRESENT result → proceed to lot. Fraud flags captured for lot-level anomaly reporting.
Outputs sig_present (bool) sig_bboxes fraud_flags
06
Vision Presentment Cross-Check
AI · Qwen2-VL Cascade
L1: cts-vision-l1 → L2: cts-vision-l2 · CascadeOrchestrator
Reads amount_figures directly from the cheque image and cross-checks against the scanner-extracted amount. Mismatch beyond tolerance → MISMATCH — routed to MismatchResolutionWorkflow (4-hour timeout, branch supervisor). Catches scanner read errors before lot is created.
Activity: run_vision_presentment_check Config: cts.presentment.amount_tolerance_paise
07
Payee Name Matching
Local NLP · No GPU
CPU · 9-script transliteration + Jaro-Winkler
Purely local — no vLLM call. Strips salutations → runs 9-script Indic transliteration → computes Jaro-Winkler similarity between OCR payee name and account title on record. Returns: MATCH · FUZZY · MISMATCH · UNDECIDABLE. FUZZY → branch supervisor; MISMATCH → reject at counter.
Activity: outward_payee_check Config: payee_match_threshold (default 0.82)
08
Lot Creation & Batch Assembly
Rule · No AI
Stateful LotManager assigns the instrument to the current clearing lot by MICR sort code / clearing zone. Generates lot sequence numbers. Lot is sealed when the clearing session closes or max instruments per lot is reached.
09
Batch Endorsement
Rule · No AI
BatchEndorsementWorkflow stamps the lot with the presentee bank's CTS-2010 endorsement: bank name, branch, IFSC, date, clearing session ID. No AI — rule-based stamping against template.
10
NGCH Submission & Session Reconciliation
Rule · ngch_filer
Lot submitted to NGCH via NGCHSubmissionWorkflow → ngch_filer activity (exactly-once, Temporal idempotency). SessionReconciliationWorkflow matches ACK from NGCH against submitted instruments. Reconciliation exceptions surfaced in RRF (Return Reason File).
Retry: max 3, exponential backoff, non-retryable: DuplicateFilingError
05 · Graceful Degradation

What Happens When Each Component Fails

No silent failure. No IET breach. Every failure path is defined, logged, and routed. The IET Watchdog files regardless of AI availability.

Component Failure Mode Immediate Response Outcome IET Risk
GOT-OCR2.0 cts-ocr queue 2 retries → return ActivityResult(outcome="HUMAN_REVIEW", degraded=True) HUMAN_REVIEW Watchdog covers
IndicOCR Stage 2 CPU sidecar Skip Stage 2 silently — use Stage 1 GOT result. Log warning. Continue with L1 OCR None
Qwen2-VL 7B (L1) cts-vision-l1 Immediate escalation to L2 (72B). No retry at L1. L2 fallback (slower) Watchdog covers
Qwen2-VL 72B (L2) cts-vision Both L1 and L2 unavailable → HUMAN_REVIEW with degraded=True HUMAN_REVIEW Watchdog covers
Alteration Detection vision cascade Both models fail → DEGRADED result returned (never raises). Route to human review. HUMAN_REVIEW Watchdog covers
Security Features Check cts-vision (72B) DEGRADED result (never raises) → ops_manager review. No automated return. HUMAN_REVIEW Watchdog covers
UV Security Analysis cts-vision-l1/l2 (Cascade) DEGRADED result → human review. UV failure never triggers auto-return. HUMAN_REVIEW Watchdog covers
Signature Vault Miss Redis vault CBS fallback → fetch specimens → embed → store → compare. If CBS also fails → HUMAN_REVIEW. HUMAN_REVIEW (never AUTO_RETURN) Watchdog covers
sig_detector (SNN) :8020 sidecar 2 retries → HUMAN_REVIEW. Vault lookup still possible from Redis if prior embedding stored. HUMAN_REVIEW Watchdog covers
XGBoost Fraud Scorer CPU direct call Rule-based fallback scorer (_rule_based_score). Returns score + shap with _source="rule_based_fallback". Rule-based score (degraded) None
Llama 3.3 70B cts-reasoning Skip rationale. Decision proceeds with score + SHAP only. Log warning. Rationale = "AI_UNAVAILABLE". Continue (score only) None
CBS Connector balance / status Image-only processing path. File to NGCH before IET. CBS check deferred to post-filing reconciliation. File before IET (image-only) Protected
NGCH Connection ngch_filer 3 retries, exponential backoff → queue in Temporal until reconnect. IET Watchdog emergency-files when T−30s reached. Queued → Watchdog files Zero breach
Full DC1 Failure — Istio + Temporal multi-cluster routes all traffic to DC2. RPO=0, RTO<30s. DC2 handles 100% Zero breach
HARD RULE: vault miss → always HUMAN_REVIEW, never AUTO_RETURN (Layer 1 enforced — no config can override)
06 · Configuration Reference

All thresholds loaded at activity start via await config_service.get_ai_config(bank_id) and await config_service.get_cts_config(bank_id). Hot-reload in 30 seconds via platform.config.changed Kafka event. Zero code change, zero restart.
