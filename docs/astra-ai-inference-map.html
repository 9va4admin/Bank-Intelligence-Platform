Signature Verification
AI · Siamese SNN
Direct HTTP :8020 · timeout: 15 s · retry: 2
Pre-processes each detected sig crop (Otsu binarisation + Zhang-Suen thinning), embeds into 512-dim vector via astra-sig-encoder-v1. Computes cosine similarity against ALL vault specimens for the account. Vault key: sig:{bank_id}:{hmac_sha256(account)}. 11
Mandate BRE (Multi-Signatory)
Rule · BRE
Business Rule Engine evaluates multi-signatory mandate: ANY_ONE (at least 1 sig matches — default / SMB), ALL_REQUIRED (every signatory must match), QUORUM_N (N of M must match). Triggered only when sig_count ≥ 2 in step 06.
12
Fraud Scoring
AI · XGBoost + SHAP
Direct call · CPU · timeout: 10 s
XGBoost ensemble scores fraud probability from structured features (OCR fields, account metadata, clearing history, anomaly flags from earlier steps). SHAP TreeExplainer always runs — values stored in decision.shap_values before any NGCH filing. Rule-based fallback if XGBoost unavailable.
Outputs fraud_score (0–1) shap_values feature_importances
13
Fraud Rationale Synthesis
AI · Llama 3.3 70B
queue: cts-reasoning · timeout: 180 s · Headroom 75–82 % compression
Llama 3.3 70B converts XGBoost score + SHAP top-N features into a plain-English explanation for the bank officer. Prompt is compressed locally by Headroom before GPU send (75–82 % token reduction). Temperature 0.1, max_tokens 300. Never includes raw account numbers or full customer names.
Outputs fraud_rationale (text) key_risk_factors
14
Decision & NGCH Filing
Decision Engine
Aggregates all AI signals against config thresholds and routes to one of four outcomes:
STP_AUTO_CONFIRM — all clear, fraud score below STP threshold → NGCH HONOUR
HUMAN_REVIEW — any signal above human_review threshold → 55-min HumanReviewWorkflow
AUTO_RETURN — clear policy violation (stopped instrument, CTS-2010 fail, kill switch)
NGCH_FILED — honour or return filed via ngch_filer activity (exactly-once)
SHAP required: always before filing Audit: Immudb write + HSM sign after every YugabyteDB write

06 · Kill Switch Architecture

Two-Level AI Kill Switch — Independent Operational Controls

ASTRA has two independent kill switches — one for Vision LLM (Qwen2-VL), one for regional OCR (IndicOCR Stage 2). They operate on different scopes, have different mode sets, and are activated by different operational triggers. A bank can silence Vision AI entirely while regional OCR continues, or vice versa — without stopping cheque clearing.

Level 1 — Vision AI Kill Switch
Applies to: Qwen2-VL (alteration detection + decision synthesis)
Implemented in: modules/cts/kill_switch/vision_ai_kill_switch.py
Activity: get_kill_switch_status() in kill_switch_lookup.py
Three Modes (hierarchy: NONE < KP < KC)
NONE — AI operates normally
KP (Kill Partial) — Qwen2-VL still called; advisory scores visible to reviewer; ALL outcomes forced to HUMAN_REVIEW (no STP). Use when AI behaviour is suspicious but you still want its read.
KC (Kill Complete) — Qwen2-VL bypassed entirely; no GPU cycles consumed. Cheque reaches human reviewer with only OCR + MICR data. Use when Vision AI is clearly misbehaving.
Three Scopes (most restrictive wins)
Scope Config key Affects
GLOBALcts.vision_ai.kill_mode.globalAll instruments (SB + all SMBs)
SB_OWNcts.vision_ai.kill_mode.sb_ownSB own instruments only
SMBcts.vision_ai.kill_mode.smb.{id}One specific sub-member only
Dual-checkpoint design — checked TWICE per cheque:
Checkpoint 1: before detect_alteration() (alteration.py)
Checkpoint 2: before synthesise_decision() (decision.py)
Reason: a KC activation during the ~120 s Qwen2-VL call would be missed by a single upfront check. The backstop at decision time catches mid-flight activations.

Every kill-switch application writes an HSM-signed AuditEvent to Immudb (event_type: CTS_KILL_SWITCH_APPLIED).
Level 2 — IndicOCR Kill Switch
Applies to: PaddleOCR Stage 2 (regional OCR refinement only)
Config key: cts.indic_ocr.kill_mode
Activity: ocr_extract() checks this at OCR time
Scope: bank-wide (no per-SMB granularity for OCR)
Two Modes
NONE (default) — Stage 2 runs when script detected
KC — Stage 2 completely skipped; GOT-OCR2.0 Stage 1 result used directly. No KP mode — OCR Stage 2 either runs or it doesn't. Advisory mode has no value here.
Key Differences from Level 1
• No KP mode (OCR is deterministic — no score to preserve)
• No scope granularity (entire bank, not per-SMB)
• Fail-open: missing config key = NONE (never blocks OCR)
• No Immudb audit write on skip (it's a config-gate, not a decision override)
• Result field indic_ocr_kill_switch_active persisted in cts.agent_decisions

08 · Immutable Explainability

Proving Every AI Decision — SHAP + Rationale + HSM + Merkle

Most AI systems can explain a decision. ASTRA can prove the explanation was never altered. The chain runs automatically on every cheque — no human trigger, no optional step.

Regulatory significance: RBI IT Framework §6.4 (AI governance) and the Basel III op-risk framework both require banks to demonstrate decision rationale on demand. ASTRA's Immudb tx_id lets an RBI examiner retrieve and cryptographically verify any decision, including its SHAP decomposition and Llama rationale, years after the fact — with mathematical proof it hasn't been touched since the moment of filing.

1
SHAP Values — XGBoost TreeExplainer
Computed by score_fraud() activity via shap.TreeExplainer. Stored in FraudActivityResult.shap_values — a dict of feature → contribution float.
Mandatory before NGCH filing — ngch_filer.py refuses to file if shap_values is empty or missing.
Even in rule-based fallback mode (XGBoost unavailable): rule contributions are structured as SHAP values (baseline, alteration_detected, low_ocr_confidence, very_high_amount…) so the record is never empty.
2
Llama 3.3 70B Rationale Synthesis — queue: cts-reasoning
Takes SHAP values + all upstream AI signals (OCR confidence, alteration tamper_risk_score, signature match score, fraud score) as structured context. Produces a human-readable rationale string (temperature: 0.1, max_tokens: 300 — precise, not creative).
Context is headroom-compressed before GPU send — 75–82% fewer tokens, local CPU, data never leaves bank cluster. headroom_reduction_pct logged in FraudActivityResult for observability.
3
HSM Signing — FIPS 140-2 Level 3
AuditEvent model is serialised to canonical JSON, then hsm.sign(bytes) is called. The private key never leaves the HSM hardware module.
HSM signature (hex) is attached as AuditEvent.hsm_signature before the Immudb write. AuditEvent.sign() raises HSMSigningError on failure — never silently skips.
The signed payload includes: instrument_id, bank_id, decision, fraud_score, shap_values, rationale, timestamp.
4
Immudb — Cryptographic Merkle-Tree Append-Only Store
ImmudbClient.write_event(payload) calls verifiedSet(key, value) — a single call that writes AND returns a cryptographic inclusion proof (Merkle path) in the same round-trip.
Returns tx_id — a globally unique, monotonically increasing transaction ID. Collection: cts_{bank_id} — per-bank isolation.
verify_event(key) calls verifiedGet(key) — re-verifies the Merkle proof on read. Raises ImmudbVerificationError if the record has been tampered.
✓
The Guarantee
Given a tx_id stored at NGCH filing time, anyone with Immudb access (including an RBI examiner with a time-scoped session) can:
  1. Retrieve the exact decision payload — decision, fraud_score, shap_values, Llama rationale, timestamp
  2. Verify the HSM signature against the bank's registered public key (certificate held by RBI)
  3. Verify the Merkle inclusion proof — mathematical proof the record was not altered after write
If any byte was changed after writing: step 3 raises ImmudbVerificationError. There is no way to silently alter a record.
AuditEvent types written per cheque decision: CTS_DECISION (always) · CTS_KILL_SWITCH_APPLIED (when KP/KC active) · CTS_HUMAN_REVIEW_DECISION (when human reviewer overrides) · CTS_NGCH_FILED (at NGCH filing) · CTS_IET_EMERGENCY (if IET watchdog fires). All HSM-signed before Immudb write. Unlimited retry policy — audit must always succeed.

Langfuse — LLM Observability
On-prem Langfuse instance — data never leaves bank cluster
Mandatory rule (ai-inference.md): every vLLM call must open a trace AND call generation.end() on every code path — including degraded/fallback paths.

What it enables:
• Per-model latency percentiles (p50/p99)
• Token cost per bank per day
• Confidence distribution over time → early drift signal
• Failure rate per queue → capacity planning
Headroom Compression
75–82% token reduction before GPU · local CPU · zero data exfiltration
File: apps/ai_server/headroom_client.py
Package: headroom (pip install headroom)
Applied: Llama 3.3 70B fraud synthesis context only
How it works:
headroom_compress(messages, model) removes redundant tokens, semantically equivalent phrases, and low-entropy context from the fraud synthesis prompt before it leaves the CPU — no GPU cycles wasted on padding.

Measured reduction on fraud rationale evals: 75–82% fewer input tokens, no accuracy loss (validated on held-out test set).

Graceful fallback: if headroom package is not installed, headroom_compress() is a no-op that returns messages unchanged. The vLLM call proceeds normally — uncompressed. No crash, no alert.

headroom_reduction_pct is logged in both FraudActivityResult and the Langfuse trace for capacity visibility.
