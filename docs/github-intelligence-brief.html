Recommendation 01

Docling

Document Structure Intelligence

MIT License IBM Research × Linux Foundation AI 37k+ stars AAAI 2025 CPU-viable · no GPU required

The gap it fills

ASTRA has strong text recognition — GOT-OCR2.0 extracts characters and Qwen2-VL 72B understands image context. What neither produces is the semantic hierarchy of a document: which block is a table header versus a cell value, which is a footnote versus body text, where a seal inscription ends and a paragraph begins. When an 8-page bank statement or trade finance LC document arrives as a flat OCR stream, Llama 3.3 70B must reconstruct structure from context — hallucination rates rise, confidence scores drop, human review volume spikes.

Docling inserts a structural intelligence layer between scan and reasoning. It does not replace your existing OCR — it makes the OCR output genuinely useful to your reasoning model.

Why it changes the platform

  • TableFormer — trained on 1M+ financial tables — recovers table structure from Indian bank statements with partial borders, empty cells, merged headers, and hierarchical column groups. Outputs machine-readable JSON with cell coordinates, not flat text runs.
  • DocLayNet includes a Seal detection class — the only open-source layout model with this label. Maps directly to authority stamps on Indian cheques, Demand Drafts, and banker's certificates. Downstream: flagging a seal vs. a text block becomes structural, not heuristic.
  • Structured DoclingDocument JSON feeds directly into your Temporal activity chain as a typed input. Llama 3.3 70B receives field hierarchy — section, table, cell, caption — not raw character runs. Field extraction accuracy improves; SHAP explanations become more precise because the feature boundaries are real.
  • CPU-viable — no GPU required for Docling itself. Runs on existing commodity server hardware without touching GPU budget or allocation. Self-hosted Docker REST server, offline mode, zero cloud calls, persistent model cache.
  • Formats: PDF, DOCX, XLSX, PPTX, images (PNG, TIFF, JPEG), HTML, email (EML/MSG) — covers the full document surface area of Indian banking operations.
Integration Path
Inbound document (PDF / image / bank statement)
→ existing GOT-OCR2.0 activity (character recognition, MICR extraction)
→ new docling_parse Temporal activity (structural JSON via Docker REST)
→ llm_reason_activity receives DoclingDocument as structured context
→ SHAP values, NGCH filing — unchanged downstream Est. engineering: 3 days · 1 new Temporal activity · 1 Docker container (CPU, no GPU) · MIT license, no revenue cap
Recommendation 02

Label Studio

Human-in-the-Loop Annotation

Apache 2.0 HumanSignal 27k+ stars ML Backend pre-labeling LDAP · data sovereignty

The gap it fills

ASTRA's feedback loop is architecturally complete: FeedbackAccumulatorWorkflow captures every decision, ModelRetrainWorkflow auto-triggers retraining, FeedbackEmitWorkflow fires after every cheque decision. The loop exists in code and in Temporal. But it has a missing link — when GOT-OCR2.0 misreads a handwritten amount in Malayalam, or confuses a cooperative bank's regional handwriting style, there is no interface for a bank operator or ml_engineer to see that error, correct it, and push a labeled example back into corpus_manager.py.

Label Studio is the annotation interface your existing feedback loop was designed for but never had. It closes the loop your architecture already planned.

Why it changes the platform

  • ML Backend API pre-labels every task using your existing GOT-OCR2.0 inference output — annotators correct mistakes only, not re-transcribe from blank. Throughput per operator increases 5–10× versus cold annotation.
  • Multi-modal in one tool — bounding box correction on cheque images, OCR transcription correction, and NER labeling on extracted text in a single interface. Eliminates three separate tools that would otherwise need RBAC, storage, and maintenance.
  • RBAC maps directly to ASTRA roles: ml_engineer manages annotation projects; ops_reviewer submits corrections from the human review queue. LDAP connector — no custom SSO integration required.
  • Export formats — COCO, YOLO, and custom JSON — match what feedback_activities.py and corpus_manager.py already expect. No format translation layer.
  • Data sovereignty — Apache 2.0, fully self-hosted. No cheque image or customer data leaves your on-prem environment. RBI data localisation: structurally compliant.
Integration Path
OCR confidence < threshold → FeedbackAccumulatorWorkflow signal
→ Label Studio task creation API (cheque image + OCR output as pre-label)
→ ML Backend auto-labels via GOT-OCR2.0 inference endpoint
→ ops_reviewer / ml_engineer corrects in Label Studio UI
→ Webhook fires → corpus_manager.py ingests labeled example
→ ModelRetrainWorkflow auto-triggers — existing Temporal flow, unchanged Est. engineering: 4–5 days · 1 Docker container · webhook integration · Apache 2.0, fully free
