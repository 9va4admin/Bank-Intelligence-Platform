ASTRA Reality Ledger — inward CTS pipeline, 21 Sep 2026

Every statement below comes from a real execution against the real local stack (Temporal, Kafka, ImmuDB, MinIO, Redis, YugabyteDB) — 20 KBL inward cheques through ChequeProcessingWorkflow on the real worker. Outcome: 19 HUMAN_REVIEW, 1 workflow failure; 0 cheques auto-decided.

Real and exercised

  • Temporal — real worker polling (after fix); 20 real workflow executions, real histories, IET watchdog child started for each, HumanReviewWorkflow + FeedbackEmitWorkflow children started.
  • Kafka — real producer + human-review consumer (non-blocking after fix).
  • ImmuDB — real connection; write_audit activity completed on 19 of 20 runs.
  • MinIO — real object store: cheque images uploaded and served by presigned URL to the activities.
  • Redis — real vault reads/writes (signature, PPS, cheque-leaf).
  • YugabyteDB — real: vault rows, config_values, cheque_leaves, agent-decision persistence.
  • OCR — real Hugging Face cloud Qwen2.5-VL-72B (config-gated dev fallback; no local GPU exists here).
  • Signature extract → embed → store → compare — real: zone crop + bbox refinement, local ResNet-18 embedding, vectors stored in vault, cosine compare at runtime (scores 0.70–0.87 observed).
  • Cheque-leaf vault, PPS vault (above bank threshold only), stop-payment, kill-switch lookup, cheque series, account status, balance — each executed in at least one real workflow.

Code ran, but partial or degraded

  • score_fraud ran once, but as the rule-based fallback: no trained XGBoost/SHAP artifact exists in this repo.
  • synthesise_decision ran once (644628) and stopped at OPA unreachable.
  • file_to_ngch reached on the stopped-cheque case; failed as retryable NGCHUnavailableError (no NGCH).
  • detect_alteration executes but is DEGRADED (no vision model on this machine; no HF fallback in that activity yet).

Stand-ins (labelled)

  • CBS — DevStubCBSConnector (dev-only fixture file). Not a bank integration.
  • Signature model — generic ImageNet ResNet-18, not the custom Siamese network CLAUDE.md specifies (none exists).
  • Account/cheque identity — seeded from the cheque filename; full A/c number is not yet extracted and MICR OCR is unreliable.
  • Mutated cases — 6 labelled fixtures (wrong signature, frozen, stopped, PPS mismatch/unregistered, leaf not issued).

Not built / not deployed / known gaps

  • OPA not deployed → any cheque reaching the decision step routes to human review (OPA_UNAVAILABLE).
  • vLLM / GPU, HSM, NGCH, Langfuse, MLflow, RedisBloom module (BF.* unsupported in dev Redis; bloom fails open).
  • Trained fraud model, trained Siamese network — never existed in the repo; earlier demos did not exercise them.
  • Migrations — ~35 files in infra/migrations/cts/ root are outside the applied chain (account vault, mismatch queue, cheque-leaf…). cheque-leaf migration applied out-of-band to the dev DB. Needs consolidation.
  • 25 bare activities registered without DI (lot/endorsement, session, SB relay, platform alerts…) receive dict input and no DB/producer. Not on the inward path; unfixed.

Why so few go deep

  • 14 of 20 stop at the OCR quality gate (date box read as the printed placeholder, amount words/figures mismatch, low payee confidence). This is HF cloud OCR variance, not a pipeline fault, but it is the main accuracy blocker.
  • 4 reach signature verification; generic-embedding scores (0.70–0.87) sit around the match threshold, so most fail verification. Expected for a non-trained embedder.
  • The stopped cheque (226663) failed the workflow at file_to_ngch after retries because no NGCH exists.
