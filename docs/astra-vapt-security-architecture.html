§ 1

System Overview

ASTRA processes Indian CTS-2010 cheques for both sides of the clearing cycle. The Inward path (Drawee Bank) must return or confirm each instrument within the RBI T+3 hour IET window — one AI agent per cheque, maximum decision time 600ms, 500 agents in parallel per batch. The Outward path (Presentee Bank) handles scanner capture, MICR extraction, lot formation, and NGCH submission.

All computation is strictly on-premises inside the bank's own data centres. No cloud dependency. No vendor access to bank data. Dual-DC active-active with RPO = 0 and RTO < 30 seconds.

§ 3

Network Topology & DC Architecture

ASTRA runs active-active across two on-premises data centres. Both DCs serve live traffic. DC3 is air-gapped and receives one-way nightly sync — it never serves traffic. Each bank is isolated in its own Kubernetes namespace pair (astra-platform-{bank_id} and astra-cts-{bank_id}) with dedicated resource quotas.

§ 4

Threat Model (STRIDE)

STRIDE analysis against key assets in the CTS pipeline. All thresholds cited (fraud score, OCR confidence, STP threshold) are pulled at runtime from config_service — no hardcoded values exist in implementation files.

ID Asset STRIDE Threat Control Residual
T-01 JWT / Session Token Spoofing Token theft enables impersonation of bank operator 15-min TTL; SAML-issued (bank IdP HSM-protected); mTLS on all endpoints; no token in logs (structlog masking enforced) LOW
T-02 JWT Role Claim Elevation of Privilege Forged role claim in JWT grants higher permissions JWT signed by bank IdP (RS256/ECDSA); signature verified on every request in shared/auth/rbac.py; role is not user-settable LOW
T-03 CTS Inward API DoS Mass submission floods CTS workers, delays IET processing Rate limit 600 req/min per bank_id at Istio Ingress; KEDA autoscaling 0→500 pods on Kafka lag >10; IETWatchdog files emergency on threshold breach regardless of queue depth LOW
T-04 Cheque Image (MinIO) Information Disclosure Exfiltration of TIFF images — contain customer PII (account number, signature, amount) MinIO SSE-KMS (AES-256); KMS key in Vault transit engine; RBAC.VIEW_PII gate on API; bucket policy: no public read; Immudb audit on every object access LOW
T-05 Signature Vault (Redis) Tampering Cache poisoning inserts false signature template, bypasses mismatch detection Keys are HMAC-SHA256(bank_id:account_number, Vault pepper) — raw account numbers never stored; Redis TLS + AUTH; Istio mTLS; VaultSyncWorkflow refreshes from Immudb-verified source daily at 06:00 LOW
T-06 Signature Vault (Redis) DoS Vault miss (key not found) escalated to auto-approve or auto-return, bypassing review vault_miss_action: HUMAN_REVIEW is a Layer 1 non-overridable constant; the setting cannot be changed to AUTO_RETURN via any admin path; code path verified by 95%+ vault tests MITIGATED
T-07 NGCH Filing Repudiation Duplicate NGCH submission — bank pays twice or creates reconciliation dispute Temporal workflow ID cts-{bank_id}-{instrument_id} enforces exactly-once; DuplicateFilingError is non-retryable; Immudb audit trail with HSM signature on every filing; NGCH filer is the only code path allowed to submit MITIGATED
T-08 NGCH SFTP Transport Tampering Man-in-the-middle on outbound SFTP connection, alters instrument data or inserts fraudulent lot mTLS client certificate issued by HSM (FIPS 140-2 L3); TLS 1.3 minimum; server cert pinned in MCP NGCH adapter config; HSM signs every CXF file before upload LOW
T-09 Immudb Audit Trail Tampering Attacker deletes or rewrites audit log to remove evidence of fraud Immudb is cryptographically append-only (Merkle tree); HSM signs each AuditEvent before write; immudb verify() detects any tree inconsistency; deletion is architecturally impossible — no DELETE API exists in Immudb MITIGATED
T-10 Layer 3 Config (Thresholds) Elevation of Privilege ops_manager lowers fraud threshold to 0.01 — all cheques auto-approve regardless of fraud score Maker-checker: ops_manager submits (maker), bank_it_admin approves (checker) — single role cannot change alone; every config change is Immudb-audited; Layer 1 keys (vault_miss_action, exactly_once_ngch) are immutable via Helm chart LOW
T-11 vLLM Inference Tampering Prompt injection via cheque image content manipulates OCR/fraud LLM output to approve fraudulent instrument Structured JSON schema enforced on all vLLM responses; confidence threshold gate from config_service — low confidence → HUMAN_REVIEW regardless of label; SHAP required before NGCH filing; Langfuse traces every inference for anomaly detection MEDIUM
T-12 CBS Connector Information Disclosure CBS connector returns full account PII which leaks into logs or API responses CBS connector is read-only via MCP (no write path); account numbers masked to ****{last4} in all structlog calls; API responses return bucketed amounts and masked accounts; VIEW_PII permission gates decryption LOW
T-13 Temporal Workflow Engine Spoofing Workflow ID collision — attacker submits same instrument_id twice to create ambiguous state Temporal enforces unique workflow IDs; a second StartWorkflow with an existing ID returns the existing run (idempotent); instrument_id generated by scanner and validated for uniqueness in check_cheque_dedup activity before workflow start MITIGATED
T-14 Kubernetes Namespaces Elevation of Privilege CTS worker pod breaks out and reaches EJ namespace, accessing EJ customer data Istio AuthorizationPolicy deny-by-default between astra-cts-* and astra-ej-* namespaces; separate Kafka consumer groups; no shared Redis or pgbouncer; OPA Rego enforces module routing LOW
T-15 Admin Console Information Disclosure Swagger UI exposed in production reveals internal API schema to attacker docs_url=None when env != "development" in FastAPI app setup; Istio Ingress only routes /v1/** and /health/** to API pods — no /docs route reaches production MITIGATED
T-11 (prompt injection) is rated MEDIUM because adversarial ML is a fast-moving threat class. Controls are strong (structured output, confidence gates, SHAP) but not formally verified. Recommend including adversarial image tests in the VAPT scope.
§ 5

Pen Test Scope & ZAP Targets

VAPT is scoped to the ASTRA application layer and its integration surfaces. NPCI NGCH infrastructure, physical HSM hardware, and third-party CBS systems are explicitly out of scope.

In Scope

  • CTS Inward API (/v1/cts/inward/**)
  • CTS Outward API (/v1/cts/outward/**)
  • Human Review API (/v1/cts/review/**)
  • Admin Console API (/v1/admin/**)
  • Authentication endpoints (/auth/**)
  • MFA endpoints (/auth/mfa/**)
  • Observability API (/v1/observability/**)
  • Audit read API (/v1/audit/**)
  • RBAC enforcement across all roles
  • JWT validation and session management
  • Rate limiting at Istio Ingress
  • MinIO bucket access controls
  • YugabyteDB SQL injection surface
  • Kafka producer authentication

Out of Scope

  • NPCI NGCH infrastructure (NPCI-owned)
  • Physical HSM hardware
  • Bank CBS (Finacle / BaNCS / FlexCube) — separate vendor
  • Bank IdP (SAML Identity Provider) — bank-owned
  • Physical network and ISP infrastructure
  • DC3 air-gapped backup systems
  • WhatsApp Business API (Meta-owned)
  • GitLab CI / ArgoCD infrastructure
  • MLflow model registry (internal; no customer data)
OWASP ZAP Scan Targets — Staging Environment
  • POST /v1/cts/inward/{instrument_id}/submit Main inward submission; IET-critical
  • GET /v1/cts/queue Human review queue; RBAC tested
  • POST /v1/cts/review/{instrument_id}/decide Human review decision
  • GET /v1/cts/decisions Agent decisions log
  • POST /v1/cts/outward/scan Outward scan submission
  • GET /v1/admin/config Layer 3 config read — RBAC critical
  • POST /v1/admin/config Maker submit — requires ops_manager
  • POST /auth/login Auth endpoint; brute-force, injection
  • POST /auth/mfa/verify TOTP MFA; rate-limit test
  • GET /v1/audit/events Audit read — compliance_officer / rbi_examiner
  • GET /health/ready Exempt from auth — verify no data leakage
Sanitised test data required: ZAP scans must use synthetic cheque images, synthetic account numbers, and a sandboxed staging Temporal cluster. Do not run active scans against a shared-cluster environment holding any real instrument data.
